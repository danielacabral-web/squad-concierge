# Step 02 — Olga Oferta: Consolidação do Master Brief

## Contexto

Olga acaba de receber as seleções do usuário (material-selection.md) e tem acesso a TODOS os arquivos de briefing do lançamento HOF Stark. Seu trabalho neste step é ler tudo, sintetizar o que importa e criar o master-brief.md que vai guiar cada criador de forma específica.

## Processo

**Passo 1 — Leitura completa do briefing**
Ler todos os arquivos de entrada sem pular nada. Identificar:
- A Big Idea central e o ângulo mestre
- Os 2 gargalos com dados precisos (incluindo dado Harvard)
- A garantia e como ela deve ser posicionada (ataque, não defesa)
- O stack completo da oferta (6 componentes + bônus HOF)
- O vocabulário obrigatório e proibido
- As urgências reais do evento (condição HOF 20-21 mar)

**Passo 2 — Síntese da oferta**
Produzir seção "Resumo da Oferta" no master-brief.md com:
- O que é o StarkOS (definição em 1 parágrafo, vocabulário obrigatório)
- Os 18 agentes do ConciergeOS e o que cada categoria faz
- A equação central: Tráfego com IA + Atendimento com IA = 30% mais pacientes
- A garantia em linguagem de ataque: "Garantimos porque controlamos as 2 variáveis"
- O mecanismo: loop de inteligência (o que é, como funciona, por que é único)

**Passo 3 — Instruções específicas por criador**
Baseado na seleção do usuário (material-selection.md), criar uma seção dedicada para cada criador ativo:

Para Paulo Palco:
- Foco do pitch (clínicas de estética / harmonização / ambos)
- Dados obrigatórios a incluir
- Momento exato do dado Harvard
- Posição e linguagem da garantia
- Tipo de demo ao vivo recomendada

Para Lara Landing:
- Foco do público (clínicas de estética / harmonização / ambos)
- Headline principal para testar (com score 4 U's estimado)
- Ordem das seções recomendada
- Urgências reais disponíveis para usar

Para Victor VSL:
- Hook visual recomendado para os primeiros 10 segundos
- Duração alvo (8 ou 12 min dependendo do acabamento selecionado)
- Ênfase no mecanismo vs. emoção

Para Artur Anúncio:
- Combinação de formatos a produzir (conforme seleção)
- Dados concretos obrigatórios em cada anúncio
- Instruções de ambiente e contexto no evento

[usar / nunca usar]

[específico para o pitch]

## Instruções para Lara Landing
[específico para a LP]

## Critérios de Qualidade

- O master-brief deve ser auto-suficiente: cada criador deve conseguir trabalhar lendo APENAS o master-brief
- A garantia nunca aparece como "se não funcionar" — sempre como "garantimos porque controlamos"
- Dados precisos citados: "Harvard Business Review", "400% menos conversão após 5 min", "18 agentes", "<30 segundos"
- Instruções para cada criador são específicas para o formato e para a seleção do usuário
- Vocabulário proibido não aparece nem uma vez no master-brief

## Condições de Veto

- Se qualquer referência ao produto como "chatbot" aparecer → reescrever como "sistema de atendimento com IA"
- Se a garantia for posicionada como defesa ("caso não atinja") → reformular como ataque ("garantimos porque somos o único sistema que fecha os 2 gargalos simultaneamente")
